# Идеи

Сюда попадает всё, что обсуждали в чате и решили не терять: гипотезы, фичи, изменения процесса. Один файл — одна идея. Файл рождается скиллом `/idea` (или руками по шаблону), живёт до статуса `converted` или `rejected` и остаётся как история решения.

Правило: задача в `tasks/TASKS.md` не появляется из воздуха — у неё есть либо идея здесь, либо источник `seo-research` / `task-run` / `project-checkin`. Ссылка на идею пишется в поле `- idea:` задачи.

## Имя файла

`YYYY-MM-DD-<slug>.md` — дата обсуждения и короткий slug латиницей (`2026-09-21-showroom-discount-code.md`). Шаблон: [\_template.md](./_template.md).

## Статусы

| Статус      | Смысл                                                                  | Кто переводит                        |
| ----------- | ---------------------------------------------------------------------- | ------------------------------------ |
| `new`       | записана, ещё не обсуждалась по существу                               | `/idea` при создании                 |
| `discussed` | варианты и последствия разобраны, решения нет                          | `/idea`                              |
| `accepted`  | владелец сказал «делаем», задачи ещё не созданы                        | `/idea` после явного «да» владельца  |
| `rejected`  | не делаем; причина в разделе «Решение», файл остаётся                  | `/idea` после явного «нет» владельца |
| `converted` | задачи созданы в `tasks/TASKS.md` (и зеркале Bitrix24), ID перечислены | `/idea` сразу после `/task-add`      |

Идея со статусом `accepted` дольше недели без задач — дрейф; `/project-checkin` подсвечивает такие.

## Разделы файла

1. **Проблема** — что болит и у кого (клиент / владелец / агент), с цифрами, если есть.
2. **Контекст** — что уже есть в коде и доках: ссылки на `docs/features/*.md`, ADR, задачи.
3. **Варианты** — 2–3 варианта с плюсами, минусами, оценкой S/M/L.
4. **Решение** — какой вариант и почему; если меняет URL / локали / схему данных / канал — ссылка на ADR.
5. **Влияние** — какие области `docs/features` затрагивает, что нужно обновить в доках после реализации.
6. **Задачи** — список `T-NNN` после конвертации.
