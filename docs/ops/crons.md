# Реестр кронов

Единственный источник истины по расписаниям. Правило: новый крон = строка здесь + один скрипт или скилл, иначе не регистрируется. Раз в неделю `cron-registry-lint` сверяет реестр с реальностью.

Три слоя исполнения, чтобы не зависеть от настольного ПК и не жечь лимиты Claude:

- **node** — детерминированные скрипты (`scripts/*.mjs`). Сейчас Windows Task Scheduler; целевое место — VPS или GitHub Actions cron (коммитят снимки в репо).
- **claude** — `claude -p "/skill"` через `scripts/daily-agent.ps1`. Не более 1 ежедневного, 1 еженедельного, 1 месячного, 1 квартального запуска плюс `task-run`.
- **b24** — роботы и бизнес-процессы Bitrix24 (SLA-алерты, напоминания, NPS-триггеры). Без Claude.
- **ext** — внешние сервисы (UptimeRobot, Merchant Center scheduled fetch).

Статус: `on` — работает сейчас, `phase0/1/2` — включается в соответствующей фазе, `later` — после 90 дней.

## Схлопнуто (не заводить отдельно)

Из ресёрча пришло ~70 предложений. Дубли объединены: все отзывы/NPS → `nps-after-delivery` + блок отзывов в `daily-ops`; все недельные отчёты (wow-report, gsc-weekly, gbp-performance-pull, hero-sku-weekly, weekly-pipeline-review, feedback-digest, form-spam-and-deliverability) → `weekly-growth-review`; все месячные (monthly-review, monthly-marketing-review, sales-feedback-monthly, legal-compliance-audit, human-capacity-review) → `monthly-retro`; все снимки данных → `collect-all`.
