# История проблем и ловушек

Не changelog релизов. Сюда пишем инциденты и грабли, на которые наступили: симптом → причина → фикс → ловушка на будущее. Новое сверху. Одна запись — одна проблема, с датой и, если есть, коммитом. Запись добавляет `/docs-sync` после задачи, где ловушка сработала, или человек сразу после разбора.

Зачем: чтобы следующий, кто пойдёт этим путём (человек или `task-run`), не тратил час на то, что уже разобрано. Перед изменением области полезно `grep` по ключевым словам здесь.

```md

```

## 2026-10-06 · `shoot.mjs` висел на `browser.close()` после снятых кадров

**Симптом.** Проверка реальных страниц: все кадры главной записаны за 25 секунд, но процесс не завершался минутами, итоговый JSON не печатался, цикл по витринам стоял.

**Причина.** Chrome (puppeteer-core) на Windows иногда не подтверждает закрытие; совпало с ленивыми картинками в горизонтальной ленте hero, которые так и не начинают грузиться.

**Фикс.** `scripts/qa/shoot.mjs` печатает итог до закрытия, ждёт `browser.close()` не дольше 5 секунд и выходит.

**Ловушка на будущее.** Внешние процессы в циклах QA — с таймаутом; результат сохранять до шага, который может зависнуть.

## 2026-10-06 · Общий хук темы перебивал правило направления: текст цены клуба исчез

**Симптом.** Скриншоты стенда тем (`qa-harness`, витрина youth): плашка «Precio club» — пустая лаймовая таблетка без текста. В Чертеже текст чипа цены клуба тоже был бы не того цвета.

**Причина.** `themes.css` сначала импортирует `concepts/*.css`, потом объявляет общие хуки. `[data-concept] [data-slot="price-club"] { color: var(--brand) }` и `[data-concept="neon"] [data-slot="price-club"] { color: var(--brand-foreground) }` равны по специфичности (0,2,0), поэтому побеждает более позднее, то есть общее правило: лаймовый текст на лаймовом фоне.

**Фикс.** Все общие хуки в `themes.css` — под `:where([data-concept])` (специфичность 0,1,0): правило направления выигрывает независимо от порядка, а утилиты Tailwind по-прежнему проигрывают, потому что правила тем вне слоёв.

**Ловушка на будущее.** Новый общий хук в `themes.css` — только с `:where([data-concept])`. Правило направления — с `[data-concept="<имя>"]`. Проверять на стенде всеми тремя наборами, не одним.

## 2026-10-06 · `robots: undefined` в метаданных страницы стирает `robots` из layout

**Симптом.** При добавлении `noindex` для витрин не-group в `metadata` layout: страницы с `generateMeta` всё равно отдавали бы индексируемый `<head>` — найдено при чтении исходников до релиза.

**Причина.** Next сливает метаданные сегментов циклом `for (const key in metadata)` (`next/dist/lib/metadata/resolve-metadata.js`, `mergeMetadata`). `generateMeta` возвращает `robots: noIndex ? {...} : undefined`: ключ присутствует, и `resolveRobots(undefined)` затирает значение родителя на `null`.

**Фикс.** Правило витрины продублировано в `generateMeta` (`noIndex || !STOREFRONT_INDEXED`) и в `metadata` layout (для страниц без `generateMeta`).

**Ловушка на будущее.** Ключ со значением `undefined` в объекте метаданных — это «сбросить», а не «унаследовать». Общие для сайта правила (`robots`, `openGraph`, `alternates`) либо ставит единый хелпер страниц, либо хелпер не должен возвращать этот ключ вовсе.

## 2026-10-06 · Рамка вокруг фото `next/image fill` не видна при `padding`

**Симптом.** В теме Неон рамка акцентного цвета вокруг фото товара (`[data-slot="stage"] { padding: 8px }`) в прототипе видна, в приложении фото закрывает её целиком.

**Причина.** `next/image` с `fill` ставит `<img>` инлайн-стилями `position: absolute; inset: 0; width/height: 100%`: абсолютный элемент отсчитывается от padding-box, а инлайн-стили сильнее правил темы.

**Фикс.** Рамка рисуется поверх фото: `[data-slot="stage"]::after { position: absolute; inset: 0; border-radius: inherit; box-shadow: inset 0 0 0 8px var(--brand) }` (`packages/themes/src/concepts/neon.css`).

**Ловушка на будущее.** Не управлять размером и положением `fill`-картинок через padding или CSS родителя: они игнорируются. Рамки и подложки — псевдоэлементом или отдельной обёрткой.

## 2026-10-06 · `mix-blend-mode: multiply` на тёмной сцене чернит фото товара

**Симптом.** При переносе прототипов в `packages/themes`: в тёмном режиме Чертежа `--stage: #15171a`, а правило `[data-slot="stage"] img { mix-blend-mode: multiply }` действует во всех режимах, и снимки на белом студийном фоне стали бы почти чёрными.

**Причина.** `multiply` умножает фото на фон сцены: на светлом фоне белые стены студии сливаются с нишей, на тёмном темнеет всё фото, включая товар.

**Фикс.** Сцена остаётся светлой и в тёмном режиме, как у Галереи и Кино (из тёмного блока blueprint убран `--stage`).

**Ловушка на будущее.** `multiply` на фото товара допустим только поверх светлой сцены. Новая тема с тёмной сценой либо выключает `multiply`, либо держит сцену светлой; цвет товара не должен меняться (правило в `packages/themes/README.md`).

## 2026-10-05 · Многоагентный прогон упал целиком и ничего не сохранил

- **Симптом:** два workflow (дизайн-концепты и стратегия) завершились с пустым результатом: все агенты упали с «You've reached your Fable limit», при повторе — «You've hit your session limit». Около 6 млн токенов работы, на диске почти ничего.
- **Причина:** агенты наследуют модель сессии; у неё кончился лимит. Агенты возвращали результат только в конце (структурированный ответ), а файлы писали в последний момент, поэтому обрыв уничтожал всю работу.
- **Фикс:** модель агентам задавать явно; каждый агент сохраняет промежуточный результат в файл сразу (бриф, отчёт, черновик), а не только в ответе; перед большим прогоном оценивать объём и дробить на прогоны поменьше. Спасти удалось то, что агенты успели записать: 5 брифов, 38 фото, 2 отчёта по архитектуре.
- **Ловушка на будущее:** «запущу 40 агентов и подожду» — риск потерять всё сразу. Безопаснее короткие прогоны с сохранением на диск и ручной сборкой результата.

## 2026-09-21 · `payload run` завершал процесс до конца seed

**Симптом.** `pnpm web seed` печатал только заголовок скрипта, exit 0, таблиц в базе не появлялось.
**Причина.** `payload run` делает `await import(script)` и затем `process.exit(0)`. Наш `run.ts` вызывал `main().catch(...)` без await — промис оставался висеть, процесс убивался до первой записи.
**Фикс.** Top-level `await main()` в `apps/web/src/payload/seed/run.ts` (1a02a01).
**Ловушка на будущее.** Любой скрипт под `payload run` должен ждать свою работу на верхнем уровне модуля; `main().catch()` без await молча теряет результат.

## 2026-09-21 · drizzle push вешает dev-сервер вопросом «create or rename»

**Симптом.** `pnpm dev` после изменения схемы (новые таблицы `pages_blocks_faq_*`, локализованные поля форм) остановился на интерактивном вопросе `Is pages_blocks_faq_items table created or renamed…`; все запросы висели, curl отдавал 000.
**Причина.** Push-режим Payload/drizzle в dev не может отличить новую таблицу от переименованной и ждёт ответа в терминале, которого у фонового процесса нет.
**Фикс.** `node scripts/ops/reset-dev-db.mjs` (дроп и создание схемы `public` только для localhost) и повторный `pnpm web seed` (1a02a01). В проде push отключён — миграции (`docs/ops/deployment.md`).
**Ловушка на будущее.** После изменения коллекций проверяй, что dev-сервер реально ответил на запрос, а не завис на промпте; локальную базу без ценных данных проще сбросить.

## 2026-09-21 · `git add -A` закоммитил worktree агентов как gitlink

**Симптом.** В коммите появились `.claude/worktrees/wf_*` как «embedded git repository».
**Причина.** Параллельные агенты создают worktree внутри репозитория; путь не был в `.gitignore`.
**Фикс.** `git rm --cached -r .claude/worktrees` и строка `.claude/worktrees/` в `.gitignore` (933c544).
**Ловушка на будущее.** Пока живут worktree, не делать `git add -A` без проверки `git status`; каталоги worktree после слияния удалять (`git worktree remove --force`).

## 2026-09-21 · Баррель `@/modules/shared/ui` тянул `payload.config` в клиентский бандл

**Симптом.** Клиентский компонент (`"use client"`) импортировал `@/modules/shared/ui`. Сборка падала на `next/cache` / `payload.config` внутри клиентского бандла: «You're importing a component that needs "server-only"…» и ошибки резолва серверных модулей в браузере.

**Причина.** Баррель `modules/shared/ui/index.ts` реэкспортировал `PayloadRedirects`, который импортирует `getCachedRedirects` из `modules/shared/api` → `unstable_cache` из `next/cache` и `getPayloadClient` → `@payload-config`. Любой клиентский импорт барреля втягивал всю серверную цепочку.

**Фикс.** `PayloadRedirects` убран из барреля `shared/ui` и импортируется только по подпути `@/modules/shared/ui/payload-redirects` из серверных страниц (`modules/pages/cms-page`, `modules/pages/product-page`). В `modules/shared/api/payload-client.ts` добавлен `import "server-only"` — теперь случайный клиентский импорт ломает сборку сразу и с понятным сообщением, а не в рантайме. Коммит `af1b99f` (scaffold).

**Ловушка на будущее.** Баррель, который импортируют клиентские компоненты (`shared/ui`, `shared/i18n`, `shared/config`, `shared/lib`), не должен реэкспортировать ничего, что тянет `next/cache`, `payload`, `@payload-config` или `server-only`. Серверные модули живут в `modules/shared/api` и импортируются по подпути; при добавлении нового серверного компонента в `shared/ui` — свой `index.ts` в папке, без строки в общем барреле.

## 2026-09-21 · Функции в словарях ломали `I18nProvider`

**Симптом.** В рантайме: «Functions cannot be passed directly to Client Components unless you explicitly expose it by marking it with "use server"». Падала любая страница, потому что `I18nProvider` оборачивает весь layout.

**Причина.** В словарях (`modules/shared/i18n/dictionaries/*.ts`) для строк с плейсхолдерами были функции вида `productsCount: (n) => n + " товаров"`. `getDictionary(locale)` выполняется на сервере, результат целиком передаётся в клиентский `I18nProvider` как проп — а через границу RSC → client проходят только сериализуемые значения.

**Фикс.** Все значения словарей — только строки; плейсхолдеры в виде `{count}`; подстановка через `interpolate(template, vars)` из `modules/shared/i18n/interpolate.ts` (`interpolate(catalog.productsCount, { count })`). Тип `XDictionary` описывает только `string`-поля, так что функция в словаре теперь ошибка TS. Коммит `af1b99f`.

**Ловушка на будущее.** Всё, что уходит в клиентский провайдер через пропсы, должно быть JSON-сериализуемым: строки, числа, массивы, плоские объекты. Никаких функций, классов, `Date`, `Map`. Плейсхолдер = `{name}` в строке + `interpolate()`, не шаблонная функция.
